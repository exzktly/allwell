# W4 — the ten items the earlier packages found and could not fix

The "Owed work found while doing this work" section of `../REVIEW_REMEDIATION.md`
holds ten numbered items that three earlier work packages uncovered while doing
something else. Item 4 (the ARCHITECTURE.md deltas) belongs to the lead and is
not touched here; the other nine are this package's list.

Two of them — items 5 and 6 — are the same defect class the whole review is
about: a shortfall that is now correctly *detected* and still cannot be *seen*.
They were done first.

## How the fixes were proved

`scripts/prove_guard.sh` compares against a base ref, and this branch's
checkpoint commits carried earlier work into that history, so a worktree of the
base contains the fix and reports "passed on the base" — a comparison that
measured nothing (CLAUDE.md §7.3 #1). The proof used instead is the one §7.7 #2
prescribes: **revert one line of the fix in place at `HEAD`, run only the tests
that pin it, and require a genuine `AssertionError` about behaviour** — not an
`ImportError` or `AttributeError` on a symbol the fix introduces, which is the
false proof §7.4 #4 warns about.

The script is `/tmp/.../w4/mutate.py`. It reverts one fix at a time, runs the
pinning tests, restores the file, and prints the failure *type* and message. All
six mutations went red with a real `AssertionError`, and the unmutated tree runs
the file green first, so a red mutation is the fix being removed rather than the
harness failing to start.

```
item 5 / renderer status      E  AssertionError: assert 'INCOMPLETE' in 'Showing channel GFP with included cell boundaries.'
item 5 / frame_load           E  AssertionError: assert [] == [('A01', 'gfp', 'raw')]
item 7 / unmeasured threshold E  AssertionError: assert not True     # the two frames were byte-identical
item 6 / QC report            E  assert False                        # nothing reached notify.status / notify.toasts
item 6 / Crop report          E  assert False
item 6 / Crop warning kept    E  AssertionError: assert ('A02' in 'Crop region set (4×4px @ (0,0)): excluded 0 of 4 …')
```

## Item 1 — `save_to_pipeline_info` was still an unlocked read-modify-write

- **Status:** done
- **Fix:** `well_viewer/domain/sample_definitions.py:138-190` — the read,
  the v1→v2 backup decision and the block replacement now happen inside a
  `_mutate` closure handed to
  `well_viewer.persistence._io.update_json_atomic`, the same guard the other
  two `pipeline_info.json` writers were converted to under item 85. The backup
  is taken *inside* the mutate, so the "was the old block v1?" test is made
  against the bytes actually being replaced rather than a copy read earlier; a
  `backed_up` flag keeps it to one backup per call even when a concurrent write
  makes the mutation run twice, which is what `update_json_atomic`'s docstring
  asks of a mutate with side effects.

  `update_json_atomic` and `atomic_write_json` gained a `durable` parameter
  (`well_viewer/persistence/_io.py:73`, `:158`) so this caller keeps the
  `durable=False` it deliberately had. It is the debounced autosave that runs
  on the GUI thread every time the user stops typing a well label, and an
  fsync per pause on a network share is a visible stall; the replace is atomic
  either way, so no reader ever sees a half-written file. Existing callers keep
  `durable=True` by default.

  `update_json_atomic` reports refusals as `False`; both callers of this
  function (the Save button's dialog and the autosave's `logger.exception`)
  key off `OSError`, so the boolean is turned back into one rather than
  becoming a silent no-op autosave.
- **Test:** `tests/test_pipeline_info_concurrent_update.py` —
  `test_saving_the_sample_definitions_keeps_the_run_s_channels`,
  `test_the_sample_definitions_write_still_lands_with_no_concurrent_writer`,
  `test_a_sample_definitions_save_that_cannot_be_written_raises`. That file
  already held the behavioural half for the other two writers and injects the
  pipeline's rewrite at the file itself — immediately after the viewer's first
  read of the sidecar — which is the seam all three writers really share.
- **Watched fail without the fix:** yes (mutation — the `update_json_atomic`
  call replaced with the exact pre-fix read-modify-write):
  `E  AssertionError: assert ['gfp'] == ['gfp', 'cy5']`.
- **Probe:** `/tmp/.../w4/p1_lost_update.py` let the pipeline rewrite the
  sidecar in the window between this function's read and its write. Before:
  `schema: old`, `fluor_tokens: ['gfp']`, `available_timepoints: [0]` — the
  run's own keys reverted, silently, with the sample-definitions block written
  on top. After: the run's keys survive (`NEW`, `['gfp', 'dapi']`,
  `[0, 24, 48]`) and the block still lands.

## Item 2 — `_collect_settings` overwrote the saved heat-map settings with defaults

- **Status:** done
- **Fix:** `well_viewer/persistence/heatmap_layouts.py:25-62` — `_tab_was_built`
  plus one guard at the top of `_collect_settings`. When the Heat Map tab does
  not exist in this session the collector hands back
  `hm.persisted_settings` unchanged instead of reading eight typed fields that
  nothing has filled in. `_BUILT_MARKERS` names the same three widgets
  `apply_persisted_settings` already tests, in one place, so the save side and

  *before* it saves — so the guard returns `{}` there and the reset is not
  undone.
- **Test:** `tests/test_heatmap_settings_survive_an_unbuilt_tab.py` (four tests,
  including one that pins the defaults as *different* from the saved block, so
  the main assertion cannot pass for the wrong reason, and one that pins the
  reset).
- **Watched fail without the fix:** yes (mutation — the guard neutralised):
  `E  AssertionError: assert {'cmap': '', …} == {'cmap': 'mag…}`, 3 of 4 red.
- **Probe:** `/tmp/.../w4/p2_heatmap.py` loaded a saved block onto the slice
  without building the tab, exactly as `load_from_data_dir` does, and asked the
  collector what it would write. Before: `{cmap: '', scale_mode: Auto, vmin:
  None, vmax: None, repset_avg: False, log_scale: False, tp_index: 0, tp_value:
  None}` against a disk block of `{cmap: magma, scale_mode: Manual, vmin: 10.0,

- **One existing test had to change.**
  `tests/test_heatmap_state_migration_a8.py::test_settings_collect_reads_the_slice`
  set the slice fields by hand *without building the tab* and asserted the
  collector returned them — which is the defect's own state, not a state the
  app reaches. It now builds the Heat Map tab first (as its sibling
  round-trip test already did) and still proves what the A8 migration guard is
  for: that the collector reads `HeatmapState` rather than the old god-object
  attributes.
