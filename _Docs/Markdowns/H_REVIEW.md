# Workstream H — adversarial review remediation

A live tracker, not a write-up. Nineteen findings from one hostile reviewer over
the workstream-H diff, most of them reproduced by that reviewer before being
reported. It exists because nineteen items is more than a session can report
honestly from memory, which is the failure `CLAUDE.md` §6.1 describes.

Counts are read off the rows. This file is deleted by the pull request that
closes its last row.

| 1 | High | The Dunnett control and both variable pickers never refill when groups or variables change | ☑ | `stats_refresh_group_list` — the funnel every group mutation goes through — now refreshes the pickers, the Statistics `on_activate` hook does too (the variables are declared on a different page entirely), and `run_stats` does once more before it reads them. | 3 | High | The H4 and H1 wired tests pass on header strings while the test itself declines | ☑ | The H4 wired test asserted three strings `paired_lines` emits *before* it knows whether anything computed, on a fixture whose constant shift the test correctly declines — so blanking all of `collect_group_values_by_variable` left it green.
