# W4 — the ten items the earlier packages found and could not fix

The "Owed work found while doing this work" section of `../REVIEW_REMEDIATION.md`
holds ten numbered items that three earlier work packages uncovered while doing
something else. Item 4 (the ARCHITECTURE.md deltas) belongs to the lead and is
not touched here; the other nine are this package's list.

Two of them — items 5 and 6 — are the same defect class the whole review is
about: a shortfall that is now correctly *detected* and still cannot be *seen*.
They were done first.

## How the fixes were proved

`scripts/prove_guard.sh` compares against a base ref, and this branch's
checkpoint commits carried earlier work into that history, so a worktree of the
base contains the fix and reports "passed on the base" — a comparison that
measured nothing (CLAUDE.md §7.3 #1). The proof used instead is the one §7.7 #2
prescribes: **revert one line of the fix in place at `HEAD`, run only the tests
that pin it, and require a genuine `AssertionError` about behaviour** — not an
`ImportError` or `AttributeError` on a symbol the fix introduces, which is the
false proof §7.4 #4 warns about.

The script is `/tmp/.../w4/mutate.py`. It reverts one fix at a time, runs the
pinning tests, restores the file, and prints the failure *type* and message. All
six mutations went red with a real `AssertionError`, and the unmutated tree runs
the file green first, so a red mutation is the fix being removed rather than the
harness failing to start.

```
item 5 / renderer status      E  AssertionError: assert 'INCOMPLETE' in 'Showing channel GFP with included cell boundaries.'
item 5 / frame_load           E  AssertionError: assert [] == [('A01', 'gfp', 'raw')]
item 7 / unmeasured threshold E  AssertionError: assert not True     # the two frames were byte-identical
item 6 / QC report            E  assert False                        # nothing reached notify.status / notify.toasts
item 6 / Crop report          E  assert False
item 6 / Crop warning kept    E  AssertionError: assert ('A02' in 'Crop region set (4×4px @ (0,0)): excluded 0 of 4 …')
```

## Item 6 — `project_verdict_column`'s failure list has no reader

- **Status:** done
- **Fix:** `well_viewer/core/notifications.py:41` (`report_verdict_failures` —
  a module-level function beside `NotificationService`, so the two callers
  cannot drift into two different sentences for one situation), called from
  `well_viewer/features/qc/controller.py:72` (`recompute_qc_all`) and
  `well_viewer/features/crop/controller.py:106` (`recompute_crop_all`).
  `apply_qc_to_cache` / `apply_crop_to_cache` now return the failed labels
  instead of discarding them.

  The crop half needed more than the call. Every crop action writes its own
  outcome to the status line one or two calls after the re-projection — five
  such lines across `set_crop_region`, `_on_crop_scope_changed` and
  `clear_crop_region` — so reporting the failure and then being overwritten
  inside the same handler would have been the same defect one layer along.
  `recompute_crop_all` returns the warning and each of those five lines appends
  it (`_appended`, `crop/controller.py:84`). The toast is raised in
  `report_verdict_failures` regardless, being the one surface the next line of
  the same handler cannot erase.
- **Test:** `tests/test_shortfalls_reach_the_screen.py` —
  `test_a_qc_reprojection_failure_names_the_well_on_screen`,
  `test_a_clean_qc_reprojection_says_nothing`,
  `test_a_crop_reprojection_failure_survives_the_status_written_after_it`,
  `test_a_clean_crop_says_only_its_own_outcome`.
- **Watched fail without the fix:** yes (mutation, three separate anchors — the
  QC call, the Crop call, and the `_appended` thread-through, which fails
  independently and is what proves the crop warning survives to the last line).
- **Probe:** `/tmp/.../w4/p6_verdict.py` gave the QC and Crop verdicts a well
  whose `shape_area` is not numeric. Before: `QC_Pass` was correctly dropped
  from that well's frame, `notify.status` and `notify.toasts` were both empty —
  the well silently stopped being gated by the thresholds the controls were
  showing. After: both surfaces carry `WARNING — QC: QC_Pass could not be
  computed for 1 well(s) (A02) …`, and the crop's own "Crop region set …" line
  carries it too.
