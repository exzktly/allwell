Rules this page follows

    Where the sources disagree, and what this example does

    QuestionThe sourcesThis example
    CapitalsApple uses title-style on buttons and segment labels. Microsoft: "Capitalize the start of every string of text in your app". Apple's own writing page: "Choose a style for each UI element type and use it consistently".Sentence-style everywhere. The app runs mainly on Windows, and it is already the majority style in the app (135 labels to 24).
    Button order in an alertApple puts the most likely choice last and Cancel first. NN/g: "Following platform conventions is more important than optimizing an individual dialog box".Drawn Apple's way here. In the app the toolkit orders the buttons for whichever system it is running on.
    Close and BackApple: do not use a text label that says Back or Close in a toolbar; use the standard symbols. NN/g: always include a visible close control.A visible ✕ and ‹ as symbols, each with a tooltip. My earlier version spelled out "Close".
    Icons or words in a toolbarApple prefers symbols. NN/g prefers icons with labels.Words. The app's eleven unlabelled header icons were one of the audit's findings.
    Switch or checkboxNN/g: a switch "should take immediate effect"; where it cannot, use a checkbox. Apple: "In general, don't replace a checkbox with a switch", and on a phone use a switch only in a list row.Switches only in the inspector's rows, where the plot changes at once. Checkboxes in every form that has a Run or Export button. This corrected one control on Batch export.
    Text inside an empty fieldApple allows a hint if a separate label is also shown. NN/g: placeholders "often hurt usability more than help it" and must never replace the label.Every field has a label outside it. "not set" appears only as a state, never as an instruction.
    How many text sizesNN/g's web guidance says no more than three. Apple gives a floor: 10 points on a Mac, 11 on a phone.Four (17, 15, 13, 12), down from five, plus the large numerals on Home's tiles. Rank is carried by weight and ink more than by size.
    Material's capitalisation ruleIts style guide would not load, so it is not confirmed.Not relied on.

    One rule the app breaks today that this example does not settle: Apple says to "avoid putting critical information or actions at the bottom of a sidebar". The well plate, the control Review depends on most, sits at the bottom of the app's sidebar. It is left out of this example; where it should live is a question for you.

    Data, paths and results are examples. This is drawn in a browser to show the language; the real app will match it in structure, colour, spacing and weight, with slightly different text rendering.
