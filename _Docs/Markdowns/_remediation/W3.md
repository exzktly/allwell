# W3 — image and frame identity, and export that does not match the screen

Fourteen items. Every code change described here is already in the working tree
(the lead checkpointed the tree into `462c2c85`, so the fixes are on HEAD).

## How the guards were proved

There is no pre-fix commit on this branch to test against: the checkpoint commit
`462c2c85` already carries this work, so a `git worktree` of the base ref
contains the fixes and reports "passed on the base", which measures nothing.
That is the `§7.3 #1` failure mode — a comparison that passes because it compared
nothing — and it happened once here before being caught.

The proof used instead is the one `§7.7 #2` prescribes for a new feature:
**revert the single line of the fix in a worktree of HEAD and require a real
`AssertionError`.** Every "watched fail: yes (mutation)" below was produced this
way, by `/tmp/.../w3/mutate.py`, which reverts one fix at a time, runs only the
tests that pin it, restores the file, and reports the failure *type*.

All fourteen mutations went red, all with a genuine `AssertionError` — not an
`ImportError` or `AttributeError` on a symbol the fix introduces, which is the
false proof `§7.4 #4` warns about. Four were re-run with the message printed, to
check each says what it should:

```
item 61      E  assert (0.0, 100.0) == (0.0, 9999.0)      # column 0's LUT on the whole row
item 57      E  assert [] == [('⊕ OVERLAY', ['GFP', 'DAPI'])]   # mark_uncorrected never called
item 56      E  assert ['A01_GFP_f1_t0.tif'] == []        # another well's image, under this label
item 102     E  AssertionError: the scale bar / identity label was dropped
```

The unmutated worktree runs all 33 new tests green first, so a mutation going red
is the fix being removed and not the harness failing to start.

## Cross-package dependencies (not fixed here)

1. **`ScanResult.partial` reaches no user-visible surface.** Item 12's flag now
   travels from `scan_zip_members` / `scan_folder_members` through `_merge_scan`
   and out of `find_well_images_and_masks`, and `_log_find_result` says so in the
   log — but a log line is what `§7` calls insufficient. Making a partially
   scanned well *look* partial needs a change in the Review consumers:
   `well_viewer/data/frame_load.py:204` and
   `well_viewer/features/image_browser/review_image/renderer.py:124`, neither of
   which is in this package. Both already unpack the four-tuple, so the change is
   additive: read `getattr(fluor, "partial", False)` and mark the well.
2. **`project_verdict_column`'s returned failure list has no reader.** Item 23
   returns the labels whose verdict could not be computed, but the two callers —
   `well_viewer/features/qc/controller.py` and
   `well_viewer/features/crop/controller.py` — discard it. The frame-level signal
   (the dropped column) is the primary fix and works today; surfacing "QC could
   not be recomputed for these 3 wells" on screen belongs to those two files.
3. **`renderer.py:483-484` coerces a `None` threshold map to `{}`.** Item 2 made
   `review_build_threshold_map` return `None` for an unmeasured field, and the
   Image Table now labels that cell. The Review Image tab's own draw path still
   turns `None` into an empty dict and paints the same all-black overlay it
   always did — no regression, but the same conflation, one surface over. The
   line is in `features/image_browser/review_image/renderer.py`, which the brief
   does not enumerate.
4. **`scatter_panel`'s per-job live combo reads** — see the sibling note under
   item 100. In scope by ownership, deliberately not swept because the fix is a
   four-signature refactor rather than a hoist, and half of it would be worse
   than none.
5. **Pre-existing, unrelated:** `_WELL_TOKEN_IN_TEXT_RE` treats a FOV field like
   `f1` as well `F01`, so `well_token_matches_text("A01_GFP_f1_t0.tif", "F01")` is
   True. That affects the *existing* token path in `_raw_file_well_passes`, not
   only the new unknown-token path, and it is in `data/image_resolver.py`. Noted,
   not touched.
