Why it feels illogical: four patterns

The same job is a different kind of surface on each page

  • Pick several timepoints / FOVs / gates: eight implementations. Some apply as you tick, some only when the menu closes. Labels vary: "Timepoints: 0 selected", "Timepoints", "All FOVs", "All gates".
  • Live view options: a Display ▾ popover on seven pages, a Layers menu with a submenu on Nanowells.
  • Brightness range: LUT ▾ popover on Cell Browser and Segmentation, a custom popover on Nanowells.
  • Save a figure: Save ▾, Properties › Export…, hover buttons on the canvas, the matplotlib toolbar, Ctrl+E. Image Table, Saved Plots and the crops pop-out each have their own differently-stocked menu.
  • Gating on Scatter is split over four surfaces: Properties (draw), Display ▾ (apply), Cell Gating (choose), Cell Browser rail (filter).

Pop-ups open pop-ups

Fold change ▾→Control combo→Per-sample dialog→Set all to ▾
Colors ▾→swatch popover→colour picker
LUT ▾→swatch popover→colour picker
Manage Remotes→Edit Remote→SSH key wizard
Delete scope ▾→3 dropdown menus
  • On a phone each of these starts inside the Controls sheet, so the chain is one deeper. Properties and Subset › Edit… each close the sheet they were tapped from and open something else somewhere else.

Things you can only find by accident

  • Right-click only: Image Table per-cell override (the app's only context menu).
  • Double-click only: edit a Heat Map tick label.
  • Hover only: copy / save buttons on every plot canvas. Nothing hovers on a phone.
  • Tap a plain label: Image Table root filter.
  • An entry inside a combo inside a popover: Per-sample control; Custom subset….
  • Appears only in some state: Decorate ▾, Excluded (n), the window strip, the Resolve guide.
  • Not reachable on a phone at all: Reset analysis, Reset view, Copy analysis, Storage, Reveal folder, Presentation look.

No fixed place for a kind of control

  • Timepoints is in the band's left zone on three pages, inside a group on Nanowells, in the rail on Cell Browser, in a toolbar in the pop-out.
  • Properties is the same icon on plot pages and Image Table and opens two different panels.
  • Three arrow conventions for "this opens a menu"; Batch Export's Quick Setup shows none.
  • Four close controls: ✕, "Close", an × icon, "Done ✕".
  • Phone layout opens from all four edges: rail from the left, Properties from the right, sheets from the bottom, ⋯ from the top.

Material 3's own bottom-sheet page could not be read (it needs JavaScript); the Material points above come from Google's earlier published guidance and summaries of it. NN/g also notes the claim that bottom sheets are easier to reach is "largely incorrect", so the case for them here is keeping the plot in view, not thumb reach.

Rules the mock-up follows

Fixed places

  • Bottom bar, four permanent slots: page picker, Wells, Controls, Share. They never move and never hide; a slot a page cannot use is dimmed, not removed.
  • Everything rises from the bottom. Properties stops arriving from the right. ☰ remains the only side panel and is navigation only.
  • Status line under the plot holds whatever is conditional today (Excluded 2, Subset, gates applied). Each chip opens the sheet page that owns it.

One sheet, pages inside

  • Depth is never more than one surface. A row ending in › pushes a page; ‹ pops it; Close is always top right.
  • Two heights: half for adjusting against the plot, full for an editor (Per-sample control, Custom subset). The grabber switches between them.
  • Every row shows its current value, so the sheet doubles as a summary of the page's state.

One component per job

  • One multi-select page (All / None, applies as you tick, row reads "3 of 8") for timepoints, FOVs, gates, layers, features, scopes.
  • One range page (min / max / Auto) for LUT and Display range.
  • One colour page (swatches, then custom) wherever a colour is chosen.

Nothing by gesture alone

  • Right-click, double-click and hover actions each get a visible row or a long-press with the same menu.
  • Canvas hover buttons become the Share menu.
  • Desk-only actions come back under ⋯ › Dataset tools, each behind a confirm alert.

Suggested build order

  1. Give the Controls sheet a page stack and the three tabs. In phone layout make_popover_button pushes its panel as a sheet page instead of dropping a menu. Twenty popovers go through that one factory, so they convert together.
  2. Move Properties into the Style tab of the same sheet (phone_panel_sheet.present becomes a tab switch), so the plot stays in view while it is styled.
  3. Add Share to the bottom bar from build_plot_save_menu, already shared by ten pages.
  4. Replace the eight multi-select builds with one picker, on the desk too.
  5. Convert the hand-built popovers (Display range, colour-map picker, swatches, colour picker) to range and colour pages.
  6. Turn dialogs that open from inside a popover into full-height sheet pages: Per-sample control, Export settings, the Subset editor.
  7. Nanowells: site detail as a half-height sheet; Layers, Problem, Excluded, Subset as rows; conditional strips as status chips.
  8. Give gesture-only actions a visible entry, and restore the desk-only actions under ⋯.
  9. Add a guard: in phone layout, a test that presses every control fails if a second popup opens while a sheet is open.

The row-by-row plan, with the code each row touches and the test that proves it, is _Docs/Markdowns/SURFACES_TRACKER.md in the repository.
